# impt_type=2 점수 정규화를 max → rank로 변경한 근거

- **작성일**: 2026-08-21
- **대상 실험**: UTKFace White/Non-White 이진, task=gender, β=3 편향 주입 (Phase 2), MobileNetV2 90% 프루닝
- **변경 내용**: 채널 점수 결합 `score = α·perf_n − (1−α)·φ_n`에서 정규화를 "레이어 max 나눗셈" → "활성 채널 순위 백분위(rank, 0~1)"로 교체 (`prune.py IMPT2_NORM`)

---

## 1. 문제 현상: α를 올렸는데 정확도가 떨어짐

α는 성능(perf)과 공정성(φ)의 혼합 비율로, α를 올리면 성능 보존이 좋아져야 한다. 실제 결과는 반대였다:

| (β=3, 90% 희소도, seed 42) | Acc | EO |
|---|---|---|
| Dense | 0.9223 | 0.0576 |
| 제안 방법 α=0.5 (max 정규화) | 0.8196 | 0.1304 |
| **제안 방법 α=0.7 (max 정규화)** | **0.7120 ↓** | **0.1435 ↓** |
| Random | 0.7516 | 0.1098 |

α=0.7이 α=0.5보다 양쪽 지표 모두 나빴고 Random에도 뒤졌다. 채널 로그(iter91)를 보면 α=0.5는 레이어별 차등 제거(features.3·5·7·12·17을 70~85%에서 보존)가 작동한 반면, **α=0.7은 거의 전 레이어가 일괄 97% 상한까지 제거**되어 정확도가 붕괴했다.

## 2. 원인 진단 (3단계, 전부 실측)

### 2-1. 채널 로그 역산 — 선택이 φ 단독으로 결정되고 있었다

각 iter 로그에는 제거된 채널의 (결합점수, 원시 φ, 원시 perf)가 기록된다. 레이어별 회귀로 점수식을 역산한 결과(`score = a·perf − b·φ`, 재구성 R² = 1.0000으로 해석 타당):

| iter01 제거 채널 기여 (중앙값) | α·perf_scaled | (1−α)·φ_scaled | 비율 |
|---|---|---|---|
| α=0.5 | 0.0030 | 0.3369 | 1 : 110 |
| α=0.7 | 0.0042 | 0.2074 | 1 : 50 |

성능 항이 사실상 0 — φ만으로 회귀해도 R² 0.96~0.99. 후반(iter45)에는 α=0.7의 일부 레이어에서 R²(φ만)이 음수로 떨어져 **순위가 노이즈화**된 것까지 관측됐다.

### 2-2. 전체 분포 직접 측정 — perf의 heavy-tail이 max 정규화에서 붕괴

dense 모델에서 φ·perf를 직접 계산해 전 채널 분포를 확인한 결과 (`channel_pruning_logs/norm_diagnostic_1iter.txt`):

- 원시 perf의 레이어 내 max/중앙값 배율: **최대 1,299배** (대부분 레이어 50~400배). φ는 4.5~27배로 완만.
- max로 나누면 **레이어 대부분에서 채널의 75~99%가 0.05 미만으로 붕괴** → α·perf 항이 죽음.

| 정규화 | α | 실효 기여 비율 (perf : φ) | 결합점수 폭 (p5~p95) |
|---|---|---|---|
| max | 0.5 | 0.09 : 1 | 0.237 |
| max | 0.7 | 0.22 : 1 | 0.183 (압축↓) |
| **rank** | 0.5 | **1.00 : 1** | 0.646 |
| **rank** | 0.7 | **2.33 : 1** | 0.677 |

max에서는 "α=0.7 = 성능 70% 반영"이 실제로는 ~18%다. rank에서는 α가 설계 의도대로 혼합 비율로 작동한다. 1 iter 제거 시뮬레이션에서도 max는 α 0.5↔0.7의 레이어 배분이 거의 동일(α가 배분을 못 바꿈), rank는 구조적으로 다른 배분을 만들었다.

### 2-3. 고성능 채널 오제거 검증 — max가 실제로 성능 채널을 자르고 있었다

제거된 채널들의 "레이어 내 원시 perf 백분위"를 시뮬레이션으로 실측:

| 정규화·α | 제거 채널 perf 백분위 (중앙값/p95/최대) | perf가 레이어 중앙값의 10배 넘는데 제거된 채널 |
|---|---|---|
| max α=0.5 | 48% / 95% / 98.7% | **13개** |
| max α=0.7 | 43% / 89% / 98.2% | 7개 |
| rank α=0.5 | 11% / 24% / 26.6% | **0개** |
| rank α=0.7 | 8% / 16% / 19.3% | 0개 |

max는 perf 상위 98 백분위 채널까지 제거한 반면, **rank는 제거를 perf 하위 27% 안에서만** 수행했다. α=0.7의 정확도 붕괴(전 레이어 균등 바닥)는 이 메커니즘의 누적 결과다.

## 3. 대안 비교: 왜 log+min-max가 아니라 rank인가

| 기준 | log + min-max | rank (선택) |
|---|---|---|
| heavy-tail 해소 | 부분적 (아래쪽 꼬리로 문제 이동) | 완전 (균등 0~1) |
| 하이퍼파라미터 | ε(log(0) 방지)·클리핑 분위수 필요 | 없음 |
| α의 실효성 | 분포 모양 따라 여전히 변동 | α = 실제 혼합 비율 (2-2 실측) |
| 크기(카디널) 정보 | log 스케일로 보존 | 순위만 보존 |
| 방법론 일관성 | 제3의 방식 추가 | impt_type=3(가중치 단위)과 동일 방식 |

rank의 약점인 **크기 정보 손실은 별도 메커니즘이 보완**한다:
1. γ 보호가 **원시 perf 기준**으로 레이어 상위 0.5%를 제거 후보에서 제외 — 카디널 정보가 꼭 필요한 최상위 구간은 원시값으로 지킴 (필요 시 γ 상향으로 강화 가능).
2. iter당 2.5%씩 91회 반복하며 **매 iter 점수를 재계산** — 단발 오판이 누적 전에 교정될 기회.
3. 그래디언트 기반 점수는 배치 노이즈가 커서 카디널 값 자체가 정밀하지 않음 — 순위가 값보다 안정적.

실제로 2-3 실측에서 "고성능 채널이 잘리는" 사고는 rank가 아니라 max에서 발생했다.

## 4. 검증 계획 (사후 확인)

1. rank α=0.7 재실행 → **α 반응 정상화(α↑ = acc↑) 여부**가 1차 검증 (max α=0.7의 acc 0.712 대비 개선 예상)
2. rank α ∈ {0.5, 0.7, 0.9} 스윕 → acc-EO 평면에서 Random(0.7516/0.1098) 대비 지배 여부 판정
3. CelebA는 dense에서 동일 진단(분포 붕괴 여부)을 먼저 확인 후 재실험 범위 결정 — 기존 max 결과는 정규화 ablation으로 보존
